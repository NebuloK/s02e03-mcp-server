S02E03 MCP Server

A remote Model Context Protocol server with memo, upload, and transcribe tools.

Tools

ToolDescriptionInputOutput
memo_write Saves a note. { text: string } { id: string }
memo_search Finds notes matching a query. { query: string } { notes: [{ id, text, created_at }] }
upload Uploads a file and returns a public URL. { filename: string, content: string (base64) } { url: string }
transcribe Transcribes audio from a URL into timestamped segments. { url: string } { segments: [{ start: number (seconds), text: string }] }

Sign-in

This server uses OAuth 2.0 for access control. Only authorized clients can call the tools.

  1. The client discovers the server via /.well-known/oauth-protected-resource.
  2. The user opens the authorization URL (/authorize) and clicks Allow Access.
  3. The client exchanges the authorization code for an access token at /token.
  4. The client includes the token in the Authorization: Bearer <token> header on every MCP request.

Data retention

Notes and uploaded files are stored in memory (and on disk for uploads). Data persists only while the server process is running. When the server restarts, all memos are reset. Uploaded files remain on disk until the instance is redeployed.

Endpoints

  • GET /.well-known/oauth-protected-resource — Protected resource metadata
  • GET /.well-known/oauth-authorization-server — Authorization server metadata
  • GET /authorize — OAuth authorization page
  • POST /token — OAuth token endpoint
  • GET /sse — MCP SSE endpoint
  • POST /messages?session_id=<id> — MCP message endpoint
  • GET /docs — This page
  • GET /health — Health check
  • GET /files/<filename> — Serve uploaded files
